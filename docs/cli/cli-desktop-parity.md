# CLI 与桌面端能力对齐矩阵

本文档明确 CLI 与桌面端 GUI 各自支持的能力范围，避免双端实现出现能力裂缝。

---

## 1. 对齐总览

| 能力域 | 桌面端 | CLI | 说明 |
|--------|--------|-----|------|
| 工具列表展示 | ✅ | ✅ | CLI 以表格/JSON 输出 |
| 工具详情查看 | ✅ | ✅ | CLI 以 `--json` 输出完整定义 |
| 安装工具 | ✅ | ✅ | CLI 支持 `--dry-run` 与 `--yes` |
| 卸载工具 | ✅ | ✅ | CLI 支持 `--purge` |
| 升级工具 | ✅ | ✅ | CLI 支持 `--check-only` |
| 启动工具 | ✅ | ✅ | CLI 支持 `--foreground` 直接查看日志 |
| 停止工具 | ✅ | ✅ | — |
| 查看状态 | ✅ | ✅ | CLI 支持 `--watch` 持续监视 |
| 查看日志 | ✅ | ✅ | CLI 支持 `--follow` 实时跟踪 |
| 环境诊断 | ✅ | ✅ | CLI 支持 `--fix` 自动修复 |
| 配置管理 | ✅ | ✅ | CLI 以命令行方式读写 |
| 修复工具 | ✅ | ✅ | CLI 支持 `--dry-run` |
| 模型配置测试 | ✅ | ✅ | — |
| 手动触发诊断 | ✅ | ✅ | `hub model diagnose` |

---

## 2. 桌面端专属能力

以下能力受限于交互形态，**仅在桌面端提供**：

| 能力 | 原因 |
|------|------|
| 安装向导可视化步骤展示 | 需要 UI 展示阶段进度与日志容器 |
| 状态徽章（StatusBadge）实时变色 | 需要前端组件渲染 |
| 模型建议的富文本展示 | 需要 HTML/Markdown 渲染能力 |
| 工具卡片（ToolCard）扫描式交互 | 需要卡片栅格与 hover 交互 |
| 设置页表单控件（开关、滑块、选择器） | 需要原生表单组件 |
| 日志搜索与高亮 | 需要前端文本处理与虚拟滚动 |
| 一键回退 / 撤销操作 | 依赖前端状态缓存与弹窗确认 |
| 系统通知（Toast / 系统通知中心） | 依赖 Tauri 通知 API |

---

## 3. CLI 专属能力

以下能力受限于桌面端形态，**仅在 CLI 提供**：

| 能力 | 原因 |
|------|------|
| 前台运行（`--foreground`） | CLI 可直接将子进程 stdout 挂接到终端 |
| 管道与脚本集成 | CLI 天生支持 stdout/stderr 重定向与 `--json` 输出 |
| CI/CD 自动化 | 无头环境无法启动 GUI |
| 批量操作脚本 | CLI 可通过 shell 循环批量处理 |
| 远程 SSH 管理 | 服务器环境通常无桌面会话 |
| 配置一键导出/导入 | CLI 可直接操作配置文件路径 |

## 4. 能力差异详述

### 4.1 安装流程

| 环节 | 桌面端 | CLI |
|------|--------|-----|
| 计划生成 | 展示 Planning spinner + 阶段说明 | 命令行 spinner + 步骤列表 |
| 计划确认 | Modal / 页面内确认按钮 | 终端交互 `Proceed? [Y/n]` |
| 执行进度 | LogViewer 实时滚动 + 步骤进度条 | 终端实时输出 + 步骤标记 `[3/7]` |
| 失败反馈 | DiagnosisPanel 富文本展示 | 终端文本 + 建议列表 |
| 重试入口 | 页面内「重试」按钮 | `hub install <id>` 或 `hub repair <id>` |

### 4.2 日志查看

| 功能 | 桌面端 | CLI |
|------|--------|-----|
| 实时跟踪 | LogViewer 组件自动滚动 | `hub logs --follow` |
| 历史查看 | 分页加载 + 虚拟滚动 | `hub logs --tail 100` |
| 按级别筛选 | UI 下拉选择 | `hub logs --level error` |
| 搜索 | 前端文本搜索 | 管道到 `grep` |
| 导出 | 前端下载按钮 | 重定向到文件 `hub logs --json > logs.jsonl` |

### 4.3 配置管理

| 功能 | 桌面端 | CLI |
|------|--------|-----|
| 修改设置 | SettingsPage 表单 | `hub config set <key> <value>` |
| 模型连接测试 | 设置页「测试连接」按钮 | `hub model test` |
| 预算查看 | 设置页展示计数 | `hub model status` |

## 5. 状态同步保证

无论通过桌面端还是 CLI 执行以下操作，状态变更必须对另一端可见：

- 安装 / 卸载 / 升级 / 修复
- 启动 / 停止
- 配置保存

### 实现机制

- 状态持久化到共享的 JSON/JSONL 文件
- CLI 修改状态后触发与桌面端相同的状态变更事件（通过文件系统监听或共享锁）
- 桌面端前端通过 Tauri Event 监听状态变化
- CLI 读取状态时直接从持久化层读取，不依赖前端缓存
